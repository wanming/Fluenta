# Safe Selection Copy Design

## Goal

Prevent Selection Actions from injecting unintended keyboard input into games or other apps while preserving the user-initiated double-`Command+C` shortcut for explicitly opening Selection Actions.

The fix must be app-agnostic. It must not depend on a Dota 2 bundle identifier, a game blacklist, or an unreliable attempt to read the system's current Game Mode state.

## Root Cause

Selection Actions currently treats mouse activity as a possible text selection. When Accessibility and browser reads return no text, the configured Force Selection fallback may post a synthetic `Command+C` through `CGEvent`.

In Dota 2, ordinary gameplay produced frequent candidate mouse selections. The selectable-text preflight was permissive enough to let those candidates continue, so the clipboard fallback posted synthetic copy shortcuts into the foreground game. Inklet's global double-copy monitor then observed Inklet's own synthetic events as if the user had pressed `Command+C`, amplifying the activity.

The runtime log confirms repeated Dota 2 candidate selections, empty selection reads, and copy-trigger events in the same intervals. The production copy fallback explicitly creates key-code `0x08` events with the Command flag and posts them at the HID event tap.

## Approaches Considered

### Game-specific exclusions

Reject. A Dota 2 blacklist fixes only the observed app and immediately fails for other games or custom-rendered software.

### Automatic game detection

Do not use as the primary safety boundary. macOS exposes keys that let a game declare Game Mode support, but it does not expose a public API that lets Inklet reliably query whether system Game Mode is currently active. Some games, including the installed Dota 2 bundle, do not publish standard game-category or Game Mode metadata. Full-screen detection would also disable Selection Actions in browsers, editors, and video apps.

### Input-safe selection behavior

Use this approach. Passive background observation must be non-invasive by default. Inklet may inspect Accessibility, run supported-browser selection JavaScript, and invoke a standard Copy menu item, but it must not post a keyboard shortcut unless the user has explicitly enabled the advanced fallback.

This rule addresses every foreground app, including games that Inklet cannot classify.

## Approved Behavior

### Automatic selection reads

The default automatic selection pipeline is:

1. Confirm that the foreground Accessibility element presents credible selectable-text semantics.
2. Read the selection through Accessibility.
3. For Safari, Chrome, and Edge, try the existing browser JavaScript reader when needed.
4. If Force Selection is enabled, invoke a standard enabled Copy menu item and observe the changed pasteboard.
5. If no safe method returns text, end silently without posting keyboard events.

An automatic mouse or keyboard selection candidate must not synthesize `Command+C` under the default configuration.

### Advanced simulated-copy fallback

Settings keeps Force Selection and adds an explicitly advanced `Allow simulated Command-C fallback` control. It is off by default for new and previously saved configurations.

The visible Force Selection picker offers `Disabled` and `Menu Copy Only`. The advanced control is available when Menu Copy is selected. When the advanced control is off, modes that formerly included shortcut fallback resolve to menu-copy-only behavior. This default applies during config migration as well as fresh installation, so an old implicit default cannot continue injecting input unnoticed.

When the user turns the advanced control on, the automatic sequence is Menu Copy followed by simulated `Command+C` only when the menu is unavailable. The setting includes localized help text warning that the shortcut is delivered to the foreground app and can affect games, remote desktops, virtual machines, and other custom input surfaces.

The existing shortcut-order enum cases remain decodable for compatibility but are not shown in the picker. A legacy shortcut-containing value without the new explicit permission migrates to Menu Copy Only. Shortcut-first behavior is retired rather than exposed as another advanced choice.

### Manual double-`Command+C`

Keep the manual gesture. Two genuine, independent user `Command+C` presses within the existing interval explicitly ask Inklet to open Selection Actions from the copied clipboard text.

The recognizer must:

- Ignore key-repeat events.
- Require a key-up between the two qualifying key-down events.
- Ignore events tagged as generated by Inklet.
- Reset incomplete gesture state after the interval expires or when monitoring stops.
- Continue to ignore ordinary single-copy gestures.

Inklet-generated `CGEvent` copy shortcuts receive a private event-source marker. The global monitor checks this marker before updating the double-copy recognizer. This prevents the optional advanced fallback from feeding back into Inklet's manual trigger.

On the first qualifying key-down, the recognizer stores the current pasteboard change count. After the second independent key-down, Inklet waits for the existing short copy-settling interval and requires both a different change count from that first observation and non-empty pasteboard text before showing the panel. This works whether the global callback observes the first copy immediately before or after the foreground app writes it: one of the two deliberate copy operations must advance the count after the stored observation. If it does not, Inklet resets the gesture without showing stale clipboard text.

### Selectable-text preflight

Tighten the preflight so generic UI and missing Accessibility data do not authorize a force-selection attempt.

Credible signals include a known text role or a supported selected-text/range capability. A missing focused element is not affirmative evidence. A generic non-empty Accessibility value on a button, window, canvas, or other non-text role is not sufficient by itself.

This preflight is defense in depth. The primary guarantee remains that passive operation cannot synthesize a shortcut without explicit opt-in.

## Diagnostics

Add focused diagnostics for copy candidates and decisions. Each relevant entry may include:

- Timestamp.
- Foreground app bundle identifier, or PID fallback.
- Key code.
- Device-independent modifier flags.
- `isARepeat`.
- Available event-source PID and user-data marker.
- Whether Inklet classified the event as user-generated, Inklet-generated, ignored, gesture-arming, or gesture-triggering.
- Pasteboard change-count outcome without clipboard content.

Diagnostics must never log typed characters, selected text, clipboard text, or other content. Repeating identical ignored events should be summarized or rate-limited so a game cannot produce an unbounded per-event log flood.

Also log when automatic selection skips shortcut fallback because the advanced setting is off. Log only the decision and source app, not selection contents.

## Configuration And Migration

Add a persisted Boolean for the advanced simulated-copy permission. Its default and missing-key decode value are `false`.

Older Force Selection enum values continue to decode. Without the new permission, both shortcut-containing legacy values normalize to Menu Copy Only. With the new permission, the effective sequence is always menu first, then the simulated shortcut. This creates a safe migration even when an older config explicitly contains a shortcut-capable ordering.

Turning Selection Actions off still removes all Selection Action global monitors. The new permission does not affect the writing-assistant hotkey or voice shortcut.

## User Interface And Localization

Add the advanced permission control to the Selection Actions settings section near Force Selection. Keep the existing restrained settings layout.

The label and help text must be localized for every language in `InkletLocalization.swift`. The help text must say that enabling the option sends `Command+C` to the foreground app and may interfere with games or remote apps.

No game list, per-game UI, or Game Mode indicator is added.

## Documentation And Privacy

Update `README.md`, `README.zh-CN.md`, and `docs/privacy-policy.md` to state:

- Automatic Selection Actions use non-keyboard methods by default.
- Simulated `Command+C` fallback requires explicit advanced opt-in.
- The foreground app receives the simulated shortcut when enabled.
- Manual double-`Command+C` remains an explicit clipboard-based trigger.
- Diagnostics record event metadata and decisions, never key or clipboard content.

Remove any wording that says the automatic fallback may simulate `Command+C` without mentioning the opt-in.

## Error And Lifecycle Handling

- Monitoring stop clears the manual double-copy recognizer and any diagnostic aggregation state.
- Disabling Selection Actions cancels pending reads and prevents new automatic fallback work.
- Switching apps during a pending read must not deliver a synthetic shortcut to the newly active app. Revalidate the source PID immediately before any opted-in synthetic event.
- If the Copy menu is unavailable or disabled, safe-default operation ends without input injection.
- If the optional synthetic shortcut does not change the clipboard, restore the previous clipboard snapshot and return an empty selection.
- Inklet-generated events never arm or trigger the manual double-copy gesture.

## Testing

Add executable focused tests before production changes.

`SelectionCopyTriggerPolicyTests`:

- A single user copy only arms the gesture.
- Two independent copies separated by key-up trigger within the interval.
- Repeated key-down events do not count as a second copy.
- Two key-down events without key-up do not trigger.
- Inklet-generated events do not arm or trigger.
- Expired and stopped gestures reset.
- Clipboard validation rejects stale or empty clipboard state.

`SelectedTextReaderTests`:

- Missing focused elements do not authorize Force Selection.
- Generic non-text roles with a non-empty value do not authorize Force Selection.
- Known text roles and credible selected-text capabilities remain accepted.

`SelectionClipboardReaderTests` and config tests:

- Missing advanced permission decodes as false.
- Shortcut-capable legacy modes cannot post a shortcut while permission is false.
- Explicit permission allows the configured shortcut fallback.
- Inklet-generated events carry the marker used by the global monitor.
- Menu-copy behavior and clipboard restoration remain unchanged.

App wiring/source tests:

- The global monitor forwards key-down, key-up, repeat, modifiers, and event-source metadata to the policy.
- Automatic reads pass the advanced permission and revalidate the source process before an optional shortcut.
- Diagnostic messages contain metadata but not event characters or clipboard contents.

Manual verification:

- With the advanced option off, play Dota 2 with Selection Actions enabled and confirm no game action bound to C or `Command+C` fires.
- Confirm diagnostic logs show skipped/ignored decisions without content or event flooding.
- Select text in TextEdit, Notes, Mail, Safari, Chrome, Edge, Terminal, and a standard editor.
- Confirm single `Command+C` behaves normally without opening Inklet.
- Confirm two deliberate `Command+C` presses still open Selection Actions with the copied text.
- Hold `Command+C` and confirm key repeat does not trigger Inklet.
- Enable the advanced fallback intentionally and verify it only runs for the original foreground process.
- Switch applications during a pending read and confirm no shortcut reaches the newly active app.

## Known Trade-Offs

With safe defaults, an app that exposes no usable Accessibility selection, is not a supported browser, and has no standard Copy menu will no longer get automatic Selection Actions through a simulated shortcut. Users who accept the foreground-input risk can explicitly enable the advanced fallback.

Manual double-`Command+C` remains globally monitored while Selection Actions is enabled. Requiring independent, non-repeated, non-Inklet-generated events and validating the clipboard keeps that explicit gesture without treating passive or synthetic activity as user intent.
